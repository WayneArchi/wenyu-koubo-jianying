# 声音清理：同时处理卡壳和断字

## 两种已出现的失败都不能复制

1. 按 ASR 逐词时间直接裁切、再把入点向后/出点向前取整到视频帧，会吃掉字头字尾。容许“少于一帧的损失”也不能算通过。
2. 为了保护字音恢复整段录音，连重复起句和失败尝试一起保留，只解决连贯，未完成去气口。

最新案例曾用额外的前后保护量减少风险，但没有完整听校；任何固定的 25、35 或 200 毫秒都不是已验证的万能算法。不要照抄单个案例的词索引、时间码、分贝阈值或片段数量。

## 用户反馈后的执行优先级（2026-10-22）

气口仍要清理，但自然连贯优先于切得短、切得密。句尾的完整发音只是底线，还要保留语气落下和自然收束；不能每句刚结束就急着接下句。允许保留少量有功能的气口，不恢复整段空转等待。

- 优先以完整句、分句、完整词组决定保留范围。ASR词级时间用于找位置，不是要求每个词单独做片段。
- 清理一句话里的卡顿后，若中间只剩一个字或单音节（例如单独的“会”），重选包含它的完整词组，或保留这处自然停顿；不能把该碎片当作正常剪辑结果。原声本来独立成句的“对”“好”等短回答需实际听校确认，不能误删。
- 相邻保留区间在原素材中连续、且画面/声音设置一致时合为一段；清理造成短片段连串时回到整句重选范围。不能只把时间线上合成复合片段来掩盖仍然碎的声音。
- 句尾先找到最后一个字完整发音和自然落音后的切点，再与下一句衔接。尾音贴边、语气悬空、后句抢进都要重做；保留量随语速和情绪确定，不统一压到0毫秒，也不机械给每句加固定空白。
- 没有实际听音能力时采取保守整句/词组方案，未解决的碎片和紧尾候选先保留完整原声单元，不以“待听校”为理由继续制造明显单字碎切。疑点保持未完成，不伪造听校记录。

## 气口清理的明确含义（用户2026-10-23纠正）

本用户所说的“气口清理”同时包含无作用的口癖、无意义重复、失败起句、卡顿和多余停顿，不只是删除静音。“不要剪碎”不等于少删或把无效表达保留下来。先判断哪些表达无新增作用并整组删除，再把保留下来的有效表达接自然；不能只追求片段少而漏掉口癖。

- “你知道吗”“对不对”“那个”等在当前句中仅为口癖时，整组删除。承担真实提问、指代、转折或情绪强调时按上下文保留，不能机械关键词全删。
- 无意义重复保留完整自然的一遍；“很困很困”“一次一次”等有真实程度或递进作用的重复不等同卡顿。
- 删除后若接缝生硬，重新选择前后完整词组和自然落音位置，保留必要停顿；不得把口癖恢复回来当作唯一解决方案，也不得逐字拼接制造孤立字音。删不干净或接不自然的点逐个列为待修，不标合格。
- 逐段记录具体删去的口癖/重复及源时间，复查整条授权范围，不能只修用户举出的前20秒。分别核验“无效表达是否清理”和“留下的发音/节奏是否自然”，任一未验证都不算声音清理通过。

## 删除什么

| 类型 | 判断 | 操作 |
| --- | --- | --- |
| 重复起句 | 前一遍未完成，后面重新开始且表达完整 | 优先保留完整自然的一遍，删除整个失败尝试，不只删几个字 |
| 自我纠正 | 前一遍表述被后一遍修正 | 保留最终真实意思及其必要上下文，不把两遍都留下 |
| 词内重启 | 如“老—老板”“这这这个” | 找到完整音节/词的实际起点，删除重启；ASR 可能漏记，须听原声 |
| 空转口头词 | “那个”“呃”“嗯”等没有语义或语气贡献 | 有可分离边界才删除；与有效音节连读时优先声音完整 |
| 有意强调 | “一个一个”“该吃吃”“真的差了很多”等具有功能 | 不按重复文本规则删除 |
| 气口/停顿 | 让句子能换气或转折的停顿有功能 | 压缩空转等待，保留必要呼吸和段落节奏 |

所有判断都回到原声，不把这张表当关键词删除列表。

## 带切口的文本确认（用户2026-10-23新增必经步骤）

每次新建或重剪草稿、实际写入剪映前，都交付完整的拟保留原话稿并等待用户确认此版本。用户仅确认标注格式或流程，不视为已确认这份稿件的具体删留。正文以最终保留文字为主体，在删除/拼接位置插入简洁的括号与删除线标记；不是按标点、字幕分行或ASR逐字时间任意加刀。

- 按用户随后简化的格式，删掉的原话直接在原位置写为“[~~我~~]”，前后保留文字照常显示。例如“[~~我~~]我今天[~~就~~]来讲这件事。”开头、结尾删除同样处理。不加“切口N”“删”“删除原因”等标签，不在正文堆时间码。源时间和理由留在内部计划，用户需要时再提供。
- 内部映射区分本轮口癖/重复清理、原有内容省略与调序跳接。待确认正文只展示本轮拟删的原话及保留内容，不把早已省略的整段重新铺进正文；真实调序或纯停顿切口若无可划掉文字，使用简短“｜”标记，并仅在稿前解释一次，不虚构被删词。
- 同一句话内部每个真实删除接缝都显示，用户能判断是否过密；连续源范围内没有删除或拼接就不虚构切口。
- 删去文字、保留文字、切口源入/出点和计划使用同一份来源映射，避免展示稿与实际执行版本不同。未能确定声学边界的点明确标“待听校”，文本同意不等于音频接缝已经通过。
- 用户确认的是这份具体稿件；确认后修改删留/调序或新增实质切口，应给出变更再确认，不借“去气口”擅自更换内容。只微调同一删除单位的声学边界、保护尾音不算重写文稿，但须保留验证记录。

## 如何落刀

1. 先确定删除单位和保留的完整说法，再映射到原片。ASR 原始词级时间戳必须保留，不用均分字幕时长猜每个字的位置。
2. 每个新切点至少带上前后完整句的局部上下文，实际回放；必要时放大波形/声谱，区分辅音、弱读、尾音、呼吸和噪声。
3. 不按“低于多少 dB”直接删声音。安静的辅音仍是有效讲话，呼吸也可能比背景声大。音量和静音检测只能筛候选点。
4. 句前约 0.2 秒作为起始参考，有空间就保留自然吸气；不要把前一个被删除词的尾音一并保留。句尾保留完整韵母及自然收尾。句内连读没有 0.2 秒空间时，不硬造空白。
5. 保留词的区间不能被帧取整向内截掉。若应用只允许帧切，选择能包含完整发音的边界；如会带入另一词，再人工调整删除单元或标待听校，不能靠放宽校验容差掩盖。
6. 不把“向外延长几毫秒”自动判为安全：它可能带入被删词的一部分。记录相邻词侵入，同样需要听校。
7. 检查跳切接缝是否出现残字、点击声、语速突变、连读丢字或过紧。不要用淡入淡出、加速、降噪或静音填补掩盖已裁掉的音节。

## 验证顺序

- 原稿与编辑稿：有没有误删观点、否定、条件或数字。
- 说话人：每段都来自目标人物；身份未明或重叠讲话不得假定已清干净。
- 每个新接点：前后原声和拼接后效果分别听，必要时修改切点；已有人工确认的切点不因机械统一参数重改。
- 从头到尾连续播放：文字稿未显示的重复音节、过密气口、逻辑突兀、视觉跳切是否存在。
- 原生工程：打开、保存后，复核真实源区间与计划一致，没有自动取整造成的截字或漏素材。

没有可用听音工具时，不声称“已经逐句听过”。可以产生标注为待听校的机器粗剪；不能标音频质量通过，也不能让用户的确认替代未做的实际检查记录。用户随后给出问题秒数时，追溯原源位置修该类问题，不只处理一个示例就声称全片清理完毕。

## 完整重录段的比较

遇到同一论点多次重录，先逐版列出共同命题、独有例子、条件、措辞完整性及表演状态。不能默认最后一遍最好，也不能为了少切几刀整段丢掉独有信息。优先选择语义完整、表达自然的版本；有价值的独有信息仍需保留或明确说明取舍。用已确认的内容方案约束选择，不能借清理气口重新删论点。

每一个新增切点都应有可说明的改善。自然停顿不是错误，不为追求密度再切一次；删去失败起句时要确认保留版本没有接着重复。B-Roll 遮住画面跳切后，声音接缝仍须独立核对。整段选择也不等于词级无损，交付时不要声称保留了全部独有信息。
