# 原生剪映草稿

## 工程范围

先确认用户要新建草稿还是修改当前草稿。不能把“重新处理”自动解释成删除重建；只有明确要求才新建或移除旧工程。修改现有草稿时记录实际草稿路径、工程 ID、主时间线 ID、轨道和素材引用，备份完整目标目录及相关索引。

使用界面或真实项目索引识别目标，不能凭文件名类似就选第一个。写入前通过正常界面保存并退出当前目标编辑状态，避免原生应用覆盖外部修改。用户正在进行未完成操作时先避免竞争，不强制杀进程。

## 运行组件的已知陷阱

读取本包 `jianying-editor` 的实际入口和运行说明。旧 JyProject 实现加载加密文件失败时，即使 `overwrite=False` 也可能进入 `allow_replace=True` 的删除重建路径；不能直接拿已有草稿试这个路径。

新建：在隔离暂存目录创建并检查完整原生项目，再以不冲突名称登记。现有草稿：使用可核验的当前原生数据或应用支持接口进行局部更新；确需 Python adapter 时采用 `script_instance` 跳过加载失败重建分支，最终必须保存并验证。不能用早先快照覆盖用户后来做的实质修改。

`add_media_safe` 的某些版本会自动 normalize/转码。源素材能原生引用时不要走这条隐式降画质路径。素材解码困难时说明具体问题，不擅自转换原片。

加密 JSON 解析失败不等于草稿损坏。无法取得可信当前数据时停止外部写入，使用原生 UI 的局部操作或说明阻塞。不要尝试“自愈”、擦除目录、整库覆盖或改其他草稿。

## 代码定位优先

用户授权直接剪辑且已有可靠源时间映射时，优先用代码生成原生片段、轨道和包装事件，一次写入正式目标时间线。不要为方便操作另建“续剪/暂存”时间线，再跨线复制回去；隔离的候选数据文件与备份留在工作目录，不增加用户需维护的成片时间线。

图片、画中画、包装字和获授权的音效统一绑定 `source_id + source_time`，按保留区间计算成片入点与时长；前文删改后重新计算映射。源锚点被删除、跨越剪口或素材不足时明确处理，不能沿用旧秒数。代码负责定位，Agent负责判断该处是否需要展示/强调；两者分别验收。只有目标剪映实测过的原生能力才写为可用。普通字幕继续走剪映原生识别与批量编辑，不能用普通text替代。

## 实际写入

- 主/子时间线、索引和缓存只按当前应用结构同步必要字段，不套另一台机器的目录或版本号。
- 同一草稿的多时间线必须在剪映原生界面真实可切换；一条视频轨里串接多个话题不算多个时间线。
- 分片使用唯一 ID，保持工程、目标时间线与素材身份；原有画面变换、美颜、音量、速度、字幕等仅按用户授权修改。
- 业务代码放当前任务工作目录。内部切点表映射 source_id、源入点/出点、成片入点/出点，时间不能越界、倒置或出现无意空隙。
- 现有变速设置必须保留。随包计划校验器仅支持恒定 1 倍速；发现非 1 倍速或变速曲线时停止此校验路径，报告目标时长映射缺项，不能强制恢复原速来通过检查。
- 原素材路径在另一台 Mac 重新解析；不复制旧机草稿中的绝对素材路径，不强行改全盘链接。
- 保存前后比较无关字段，确保只改当前授权的片段、时长和必要索引。

本机 11.6 保存后会建立 `Timelines/project.json` 与 `Timelines/<主时间线ID>/draft_info.json`。后续只有根 `draft_info.json` 改了，界面可能继续显示旧主时间线。更新前读取实际主时间线 ID 和时间线数量，备份关联文件，按当前授权同步必要路径；不能遍历覆盖所有时间线。原生数据已加密时，不能以旧明文覆盖用户后续实质修改。本次新建测试仅在明确没有用户内容改动、原文改字测试已恢复且有完整备份时，同步任务自己生成的新版字幕。

## 原生复制、轨道与用户共同操作

跨时间线复制粘贴后，必须检查新增片段实际落在哪条轨道，不能把“画面出现/粘贴成功”当成已归到目标主轨。串接原片的任务应核对新增视频与既有视频在同一指定主轨，顺序与源范围正确，接缝无意外空隙、重叠或覆盖，字幕/音频没有错位或重复。若目标本来要求副轨或画中画，则按其授权核对，不能一律强移到主轨。剪贴板可能按所选起点和粘贴游标偏移，新增文字也须核对落点与层级。

文宇已要求本工作流在每条新建时间线上打开“主轨吸附”：新建或首次打开目标时间线后逐条检查并开启，切换回来核验保持；交付重开时再确认。代码片段连续不等于开关开启，另一条时间线已开启也不代表新线继承。区分“主轨吸附”和“自动吸附”，不能用后者已亮代替前者状态。此为本用户工作流偏好，其他客户或明确要求关闭的任务按对应授权处理。

依据当前截图和可见UI状态定位轨道、片段与接缝，不沿用旧坐标盲拖。每次粘贴、拖动、删除或吸附切换等逻辑操作后立即验证，再决定下一步；一次操作一次验证，不连续多次试拖后才猜结果。发现落轨或落点不对，先重新读当前状态，记录可恢复的已知错误，不扩大选择范围乱试。

用户参与修改或界面发生外部变化后，重新读取截图/可访问性状态，更新片段与轨道定位，废弃旧坐标及旧动作队列。不得Cmd+Z撤销用户的人工修改；只有能确认是Agent自己的错误、且没有夹杂后续人工修改时，才针对该错误恢复并重新核对。无法确认归属时保留现状、说明具体问题，不用盲目撤销改变用户成果。

拖动由用户代为完成时，如实记录人工协助和Agent尚不稳定的能力，不能记成端到端无人协助通过。具体本轮案例见包内验证状态，通用规则不依赖该案例的固定坐标、片段数或时长。

## 文字选择与字号调整

调整字幕或花字字号前，先点击当前界面空白处清除旧多选，再只选择本次目标字幕/花字。依据当前截图和选中状态核对没有混入视频、音频或其他片段，并确认右侧确为文字属性，能定位真实字体与字号控件，才修改字号。不能沿用旧选择、旧字段索引或旧坐标直接输入。

视频与文字混选时可能显示等比缩放等变换控件，等比缩放不是字号，不能用它替代本次字号调整。文字本身的字号、画面/片段变换与动画关键帧分别核对，不为改字大小意外缩放视频或改掉既有关键帧。多选可用于确需同样改动的同类文字，不能因为控件能点击就判定选择范围正确。

输入位置、字号等数值前，还须确认参数框真正进入输入状态。点击可见参数框后，优先重新读取AX输入节点与对应当前数值；本机剪映11.6见过`automationfirstTextInput/secondTextInput`，节点和值必须对应这次所选参数，不能硬套旧编号或仅凭点击坐标判断。若自绘数值框不暴露AX，必须取得新截图，看清目标字段的当前数值确已被选中，再用`typeText`输入；没有AX不等于可以省去焦点证据。两种路径都无法确认时停止该次输入，不盲目Cmd+A或粘贴。已确认AX的数值输入也优先用typeText，避免剪贴板仍存整组素材时误粘到时间线；截图回退必须用typeText。

参数框未聚焦时，Cmd+A与粘贴可能仍作用于时间线，造成片段复制。发生时只恢复能明确归属Agent的该次错误粘贴，随后核对时长和原素材布局；不得连带撤销用户已修好的主轨或其他人工修改。输入后读取实际值并看预览，未达到目标时重查焦点和选择范围，不连续重试；不能把一次数值修改成功当成该输入路径已稳定。

遇到意外的“重置关键帧”等对话框，取消未预期操作，重新核对选择和文字属性，不随手提交或盲目重试。操作后检查所选字体/字号和预览，并核对无关视频、文字、主轨及既有关键帧未被连带改变；只记录实际查看的范围，不凭关闭弹窗声称全工程无误。

## 本机 UI 编辑经验

剪映自绘文本框的 AX focus 不总代表实际键盘焦点。改中文标题时，先坐标点击可见文字区域，再全选并读取“Selected text”验证内容；随后用 paste 写入中文并回读实际内容。此次 typeText 中文只留下标点，不能把调用成功记作写入成功。数值输入仍按前述焦点证据规则使用 typeText。

弹出字体列表/菜单后，截图所示窗口与旧 app 绑定的输入窗口可能不一致。先重新绑定当前窗口再按其新截图操作，关闭弹窗后再绑定主窗口；不按旧窗口坐标连续猜点。

## 验证

先检查计划和原生区间一致；再在目标 Mac 的剪映中实际打开草稿，确认素材可见、方向正确、没有媒体丢失、时间线数量和时长正确。原生保存后重新读取或重开，检查应用是否取整、重写或丢弃某些字段。

软件版本兼容只以目标机实测为准。包内运行组件不是剪映官方稳定 API；历史上能打开不保证另一版本也可用。只做到结构写入时交付状态写“已写入，未验证原生打开”。能打开但未听校则写“待听校粗剪”。不能用“草稿成功”省略真实状态。

UI 自动化结束后释放控制会话，保留用户正在查看的工程。不要无必要导出完整视频做反复技术测试；仅需要检查切点时处理小段代理音频并记录其对应源范围。
